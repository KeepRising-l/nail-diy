## 三、功能实现详解

### 3.1 用户认证与三级鉴权

**技术**：Spring Security 6 + JWT（无状态）+ BCrypt

**实现要点**

1. **认证过滤器** `security/JwtAuthenticationFilter.java`
   - 继承 `OncePerRequestFilter`，从 `Authorization: Bearer <token>` 解析
   - 校验通过后把用户身份写入 `SecurityContext`：
     ```java
     new UsernamePasswordAuthenticationToken(
         userId, null, List.of(new SimpleGrantedAuthority("ROLE_" + user.getRole())));
     ```
   - 启动时校验密钥强度（`@PostConstruct` + `JwtUtil.validateSecret`），**弱密钥直接拒绝启动**

2. **授权规则** `security/SecurityConfig.java`
   ```java
   .requestMatchers("/api/auth/**", "/api/health", "/uploads/**").permitAll()
   .requestMatchers(HttpMethod.GET, "/api/templates/**", "/api/materials/**", "/api/notices").permitAll()
   .requestMatchers("/api/merchant/**").hasAnyRole("MERCHANT", "ADMIN")
   .requestMatchers("/api/admin/**").hasRole("ADMIN")
   .anyRequest().authenticated()
   ```
   - 会话策略 `STATELESS`，关闭 CSRF
   - 401 / 403 统一返回 JSON（而非 Spring 默认的 HTML 错误页）

3. **前端守卫** `router/index.js`：`meta.requiresAuth` + `meta.roles` 双层校验，未登录跳登录并带 `redirect`

**测试覆盖**：`JwtUtilTest`（5 个用例）覆盖过期、签名错误、弱密钥、畸形 claim。

### 3.2 可视化设计台（核心模块）

**技术**：Vue 3 + 自研参数化 SVG 渲染引擎

**这是全项目技术含量最高的部分**。甲片的所有视觉维度都不是"切好的图"，而是**纯函数按参数实时生成 SVG**。

#### 3.2.1 渲染引擎：四个模块

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 甲型轮廓 | `engine/contours.js` | 8 种甲型的参数化 SVG path |
| 参数化款式 | `engine/patternStyles.js` | 10 种款式生成器 |
| 效果覆盖层 | `engine/polishOverlays.js` | 20 种覆盖层（GLOSS/PEARL/SHIMMER/EFFECT/SPECIAL） |
| 钻饰 | `engine/decoGems.js` | 水晶切面渲染 |

#### 3.2.2 关键设计一：甲型与长度解耦

```js
// contours.js —— 甲型 = 参数化 path，长度是独立系数 k
export const SHAPE_CONTOURS = {
  almond(k) {                    // 杏仁形
    const t = 76 * k + 4, m = f1((4 + t) / 2)
    return `M 10.5 4 C 8.5 ${m} 15 ${f1(t - 12)} 25 ${f1(t - 4)} Q 30 ${f1(t)} ...`
  },
  // 其余 7 种同构
}
export const clampLength = (k) => Math.min(2.8, Math.max(0.6, Number(k) || 1))
```

- **统一几何基准**：最宽处 x∈[8,52]（44 单位），甲根缘 x∈[9,51]（宽 42，与最宽处仅差 5%）—— 穿戴甲必须完整覆盖天然甲床，根部不能明显收窄露甲
- **长度系数 k∈[0.6, 2.8]**，`viewBox` 高度随 k 伸缩：`contourHeight = round(76*k + 8)`
- **收益**：8 种甲型 × N 种长度只需 8 个函数，而非 8×N 张图。产品上表现为"短杏仁形 / 长杏仁形都属于同一种杏仁形"

#### 3.2.3 关键设计二：效果层可叠加

```js
// NailArt.vue —— OVERLAY 层栈，支持多选叠加
overlays: [{ id, opacity }]     // 而非单选的 overlayId

// 渲染时按层遍历，统一裁剪进甲片轮廓
<g v-for="ov in overlayRenders" :key="ov.id" :opacity="ov.opacity">
  <image v-if="ov.image" :href="ov.image" ... />     <!-- 有 PNG 走图片 -->
  <g v-else>...</g>                                   <!-- 无 PNG 走参数化 -->
</g>
```

- 20 种效果层全部半透明，**珠光 + 细闪 + 极光可同时存在**
- **双通道**：`image_url` 为空走代码渲染，有值叠加透明 PNG —— 业务数据结构不变，**素材到位后只换素材源**

#### 3.2.4 关键设计三：可复现的随机

```js
// utils/color.js —— 种子随机，同一设计每次渲染完全一致
export const seededRandom = (seed) => { /* 线性同余 */ }

// 使用
const rnd = seededRandom(props.index * 97 + n * 13)
```

避免"刷新一次，波点位置全变了"。

#### 3.2.5 关键设计四：甲片分层渲染顺序

`components/NailArt.vue` 的渲染顺序（从底到顶）：

```
① 底色 / 渐变          ← COLOR 色卡（30 色）
② 猫眼磁吸光带         ← 角度/宽度/亮度可调
②.5 参数化款式         ← patternStyles 引擎
③ 法式微笑线           ← 高度/弧度可调
④ 波点 / 豹纹          ← 密度/大小可调
④.5 效果覆盖层         ← polishOverlays 引擎（可叠加）
⑤ 贴花图案             ← PATTERN_IMG 素材，可拖动落点
⑦ 凝胶顶胶高光         ← 固定渲染，随甲型裁剪
```

全部包在 `<g clip-path="url(#clip)">` 内，**任何图层都自动被甲片轮廓裁剪**。

#### 3.2.6 交互能力

| 能力 | 实现 |
| --- | --- |
| 撤销 / 重做 | 历史栈 `history[]` + `histIdx`，每次操作 `pushHistory()` 存快照 |
| 同步到全部手指 | `syncAll()` 把当前手指配置复制到五指 |
| 拖拽投放素材 | HTML5 drag & drop，按落点百分比定位 |

| 拖动选色 | pointer 事件监听，横向色相 + 明度滑条 |

### 3.3 手模逐指嵌入几何

**技术**：位图手模 + SVG 甲片槽位 + 几何映射 + 甲缘遮罩

**文件**：`components/HandModel.vue`

#### 3.3.1 问题

常规做法是把一个椭圆 SVG 贴在手指上 —— 视觉上就是"贴纸"。

#### 3.3.2 解法：逐指实测 + 几何映射

```js
// 五指参数全部从手图（1278×1230）逐指实测
const FINGERS = [
  { idx: 0, x: 315.8, y: 356, bedW: 40, bedL: 79,  angle: -5.5, tone: '#F7D5C5' }, // 小指
  { idx: 3, x: 535.0, y: 206, bedW: 50, bedL: 93,  angle: 9.5,  tone: '#F7D5C4' }, // 食指
  { idx: 2, x: 708.8, y: 150, bedW: 58, bedL: 117, angle: 11.4, tone: '#F6D2C0' }, // 中指
  { idx: 1, x: 876.0, y: 262, bedW: 57, bedL: 98,  angle: 18.9, tone: '#F7D6C5' }, // 无名指
  { idx: 4, x: 983.3, y: 714, bedW: 70, bedL: 90,  angle: 38.8, tone: '#EBBFAC' }  // 拇指
]
```

| 字段 | 含义 |
| --- | --- |
| `x, y` | 天然甲缘线中心（甲片根部的固定锚点） |
| `bedW` | 天然甲床轮廓外缘宽度（px） |
| `bedL` | 甲床甲缘到指尖长度（px） |
| `angle` | 甲床长轴与竖直方向夹角（拇指为大斜角 38.8°） |
| `tone` | 该指甲缘旁肤色取样（用于甲缘遮罩融入） |

#### 3.3.3 三个关键机制

**① 根部锚定 + 绕甲根旋转**

```js
const back = ROOT_CENTER_Y * f.s              // 沿指轴后移，使甲片根缘落在甲缘线上
const ax = f.x - Math.sin(rad) * back
const ay = f.y + Math.cos(rad) * back
transform: `translate(-50%, 0) rotate(${f.angle + 180}deg)`
transformOrigin: '50% 0'                      // 绕甲根旋转，不是绕中心
```

**② 长度只向指尖延伸（不做整体 scale）**

```js
function slotLenFit(i) {
  const f = FINGERS[i]
  return L => {
    const l = Math.min(1.6, Math.max(0.6, Number(L) || 1))
    const dBed = l <= 1
      ? 1.02 + 0.35 * (l - 0.6)                 // 基础段：贴合 → 标准
      : 1.16 + 2.0667 * (l - 1.0)               // 加长段：标准 → 极长
    const k = (dBed * f.bedL / f.s + 3) / 76
    return Math.min(2.8, Math.max(0.6, k))
  }
}
```
- **根部位置与宽度不随长度变化**，只有尖端延伸
- 分段映射保证 L=0.6 贴合指尖、L=1.0 标准（覆盖甲床 + 约 16% 延伸）、L=1.6 加长（约 2.40× 甲床长）

**③ 甲缘遮罩产生"嵌入感"**

```html
<!-- 肤色新月 + 破皮交接线 + 高斯模糊，盖在甲片根部之上 -->
<path :d="cuticlePath(f)" :fill="f.tone" filter="url(#hm-soft)" />
<path :d="foldLinePath(f)" stroke="rgba(163,102,72,0.20)" filter="url(#hm-soft)" />
```
- 甲缘肤色新月从掌侧皮肤跨到甲面上约 2u 处
- 甲片像"从皮肤里长出来"，而非贴在表面
- 同时甲片宽度 = `bedW + 3px`（完整覆盖甲床，又不过分超出手指）
- 嵌入态 `outlined=false`，不画描边，靠 `drop-shadow` 表现边缘

### 3.5 订单状态机与履约

**技术**：纯 Java 规则表 + Spring 声明式事务

**文件**：`service/OrderStateMachine.java`

```java
private static final Map<String, Set<String>> RULES = Map.of(
        STATUS_PENDING_PAY, Set.of(STATUS_PAID, STATUS_CANCELLED),
        STATUS_PAID,        Set.of(STATUS_PRODUCING, STATUS_CANCELLED),
        STATUS_PRODUCING,   Set.of(STATUS_WAIT_PICKUP, STATUS_WAIT_SHIP),
        STATUS_WAIT_PICKUP, Set.of(STATUS_VERIFIED),
        STATUS_WAIT_SHIP,   Set.of(STATUS_SHIPPED),
        STATUS_SHIPPED,     Set.of(STATUS_RECEIVED));

public static void assertTransition(String from, String to) {
    Set<String> allowed = from == null ? null : RULES.get(from);
    if (allowed == null || !allowed.contains(to)) {
        throw new BusinessException(ILLEGAL_TRANSITION);
    }
}
```

**设计价值**
- 全系统**唯一**流转规则，杜绝散落的魔法判断
- 终态（VERIFIED / RECEIVED / CANCELLED）无出边
- 未知 / 空状态等脏数据一律拦截

**自提码**

```java
// 制作完成 → 自提订单生成 6 位全局唯一自提码
String pickupCode = generatePickupCode();   // 重试直到不重复
// 核销：码错拒绝，成功即终态
if (!pickupCode.equals(order.getPickupCode())) throw new BusinessException("自提码不正确");
```

**并发防护**
- 购物车首次插入用 `DuplicateKeyException` 捕获 + 条件更新重试
- 订单状态更新校验 `from` 状态，**陈旧状态不写误导性日志**（有单测覆盖）

**测试覆盖**：`OrderStateMachineTest` 用**参数化测试**遍历全流转表（合法流转 / 终态封口 / 非法跳转 / 未知状态）。

### 3.6 素材中台与 UGC 审核

**技术**：统一素材表 + 审核状态机 + 私有目录隔离

#### 3.6.1 素材统一建模

```sql
CREATE TABLE material (
  type VARCHAR(20),        -- SHAPE/COLOR/PATTERN_IMG/PATTERN_STYLE/DECOR/STICKER
  code VARCHAR(50),        -- 绑定前端渲染器（代码注册素材）
  image_url VARCHAR(255),  -- 图片类素材
  color_code VARCHAR(20),  -- 色卡
  attrs JSON,              -- 类型专属属性
  source VARCHAR(20),      -- PLATFORM/UGC/AI
  audit_status VARCHAR(20),-- PENDING/APPROVED/REJECTED
  ...
)
```

**扩展点**：新增美甲品类只需加一个 `type` 值 + 前端一个渲染器，**不改表结构**。

**两类素材**
| 类型 | 存储方式 | 预览 |
| --- | --- | --- |
| 代码注册素材（甲型/款式/矢量装饰/效果层） | `code` 绑定前端渲染器，不存图 | `MaterialThumb` 用 `contours.js` 现画轮廓 |
| 图片素材（贴图/贴纸/立体装饰） | `image_url` | `el-image` |

#### 3.6.2 UGC 审核流

```
顾客上传透明底 PNG
   → 存 private-uploads/（不映射静态资源）
   → material 记录 PENDING
   → 商家审核
       ├─ 通过 → APPROVED，全员可见
       └─ 驳回 → REJECTED，对上传者隐藏
```

**可见性规则**（`MaterialService.imagePath`）
```java
boolean publicImage  = status == 1 && AUDIT_APPROVED.equals(auditStatus);
boolean pendingOwner = AUDIT_PENDING.equals(auditStatus) && viewerId.equals(creatorId);
if (!publicImage && !pendingOwner && !operator) throw new BusinessException(NOT_FOUND);
```
- 审核通过 → 公开
- 待审 → 仅上传者本人 + 运营角色
- 其他 → 404（不暴露存在性）

**兼容旧数据**：`WebConfig` 注册 `/uploads/**` 拦截器，防止通过已知 URL 绕过审核状态访问历史 UGC 图片。

### 3.7 文件上传安全

**文件**：`service/FileService.java`

| 风险 | 防护手段 |
| --- | --- |
| 路径穿越 | `canonicalUploadPath` 逐段校验，拒绝 `.` / `..` / 非 `[A-Za-z0-9._-]` 字符 |
| 伪装图片 | 校验文件头魔数 **且** 用 `ImageIO` 真实解码，扩展名必须与内容一致 |
| 透明底贴纸 | 逐像素扫描，**必须含透明像素**，否则拒绝 |
| 资源耗尽 | 尺寸 ≤ 4096×4096，单文件 ≤ 5MB |
| 越权读取 | 私有目录文件统一走接口鉴权，不直接暴露 |

**上传路径规范**
- 公开素材 → `uploads/yyyyMMdd/<uuid>.png`，返回 `/uploads/...`
- 私有贴纸 → `private-uploads/yyyyMMdd/<uuid>.png`，返回 `private://stickers/...`（内部标识，前端拿不到真实路径）

**测试覆盖**：`FileServiceTest`（7 个用例）覆盖格式校验、透明校验、尺寸限制、路径穿越。

### 3.9 售后与消息通知

**技术**：状态机式审核流 + 条件更新并发防护 + 轻量通知方案

#### 3.9.1 售后申请与审核

**文件**：`entity/AfterSale` · `service/AfterSaleService` · `controller/AfterSaleController` / `MerchantAfterSaleController`

**状态流转**

```
PENDING（顾客提交，待商家处理）
  ├─ 商家同意 → COMPLETED（已退款，终态）
  └─ 商家拒绝 → REJECTED（终态）
```

**关键设计**

| 设计点 | 做法 | 为什么 |
| --- | --- | --- |
| 退款金额 | 后端按 `order.totalAmount` 计算，DTO 里**根本没有金额字段** | 防止客户端伪造退款金额 |
| 一单一售后 | 提交前按 `orderId` 计数校验 | 避免反复提交骚扰商家 |
| 可申请范围 | 仅 `RECEIVED` / `VERIFIED` 状态 | 未完成订单走取消流程，不走售后 |
| 并发防护 | 条件更新 `WHERE id=? AND status='PENDING'` | 两个审核请求并发时只有一个生效 |
| 归属校验 | `!userId.equals(order.getUserId())` → 404 | 不能对别人的订单发起售后 |

**并发防护实现**（与素材审核同风格）

```java
// AfterSaleMapper
@Update("""
        UPDATE after_sale
        SET status = #{status}, reject_reason = #{rejectReason}, handle_time = NOW()
        WHERE id = #{id} AND status = 'PENDING' AND deleted = 0
        """)
int handlePending(@Param("id") Long id, @Param("status") String status,
                  @Param("rejectReason") String rejectReason);
```

```java
int updated = afterSaleMapper.handlePending(id, status, rejectReason);
if (updated != 1) {
    throw new BusinessException("该售后单已被处理，请刷新后重试");
}
```

**订单侧集成**：`OrderVO` 增加 `afterSaleStatus` 字段，`OrderService.toVO` 只 `select` 状态列查询，
前端据此决定是否显示「申请售后」按钮与售后标签 —— 避免前端为每个订单单独发请求（N+1）。

#### 3.9.2 消息通知

**文件**：`entity/Notification` · `service/NotificationService` · `controller/NotificationController`

**方案选型：为什么不做 WebSocket**

| 方案 | 成本 | 结论 |
| --- | --- | --- |
| WebSocket 实时推送 | 需维护长连接、心跳、断线重连、集群广播 | 对毕设规模过重 |
| **轮询 + 未读红点** | 一次接口调用，对现有架构零侵入 | **采用** |

**实现要点**

1. **埋点集中在 OrderService** —— 状态变更后调用 `notifyCustomer` / `notifyMerchants`：

```java
private void notifyCustomer(Order order, String title, String content) {
    notificationService.send(order.getUserId(), Notification.TYPE_ORDER, title, content,
            order.getId(), Notification.BIZ_ORDER);
}
```

2. **通知失败不影响主业务** —— `send` 内部捕获异常只记日志：

```java
public void send(Long userId, String type, String title, String content, Long bizId, String bizType) {
    try {
        notificationMapper.insert(n);
    } catch (Exception e) {
        log.warn("通知写入失败 userId={} title={}", userId, title, e);
    }
}
```

> 这一点很重要：若通知写入异常直接抛出，会把订单状态变更的事务一起回滚 ——
> 因为一条通知写不进去而让订单状态变更失败，是明显不合理的。

3. **前端交互** —— 顶栏铃铛 + `el-popover` 下拉，打开面板时拉最新 8 条并标记全部已读：

```js
async function onOpenNotifications() {
  const res = await request.get('/notifications/latest', { params: { limit: 8 } })
  notices.value = res.data || []
  if (unreadCount.value > 0) {
    await request.post('/notifications/read-all')
    unreadCount.value = 0
  }
}
```

4. **通知埋点清单**

| 触发点 | 接收方 |
| --- | --- |
| 支付成功 / 顾客取消订单 | 商家 |
| 接单 / 制作完成 / 发货 / 核销 | 顾客 |
| 商家取消订单 / 顾客确认收货 | 顾客 / 商家 |
| 提交售后申请 / 售后审核结果 | 商家 / 顾客 |

### 3.10 统一响应与异常处理

**技术**：`@RestControllerAdvice` + 统一响应体

```java
// 统一响应：{ code, message, data }
public class Result<T> { ... }

// 全局异常：业务异常 / 参数校验 / 路径不存在 / 兜底
@ExceptionHandler(BusinessException.class)
public ResponseEntity<Result<Void>> handleBusinessException(BusinessException e) {
    return build(e.getCode(), e.getMessage());
}
```

- **HTTP 状态码与业务 code 保持一致**（4xx/5xx），便于网关与监控识别
- 绝不把堆栈抛给前端
- 前端 Axios 响应拦截器统一读取 `error.response.data.message` 提示用户，401 自动跳登录

## 四、项目亮点总结

### 亮点一：自研参数化渲染引擎（技术深度）

**不是调用现成组件，而是自己写了四套渲染引擎。**

| 亮点 | 说明 |
| --- | --- |
| 甲型与长度解耦 | 8 种甲型 = 8 条参数化 path，长度是独立系数 k，不需要 8×N 张图 |
| 效果层可叠加 | 20 种效果层全部半透明 SVG 元素，可任意组合叠加 |
| 可复现 | 种子随机保证同一设计每次渲染一致 |
| 可演进 | 「参数化渲染 + PNG 无缝替换」双通道，业务结构不变 |

### 亮点二：手模逐指嵌入几何（工程细节）

逐指实测锚点/宽度/角度/肤色 + 根部锚定甲缘线 + 长度只向指尖延伸 + 甲缘遮罩 —— 解决了"甲片像贴纸"的视觉问题。

### 亮点三：设计快照化（产品机制）

把"设计态"在时间轴上冻结，从机制上消除定制品"设计-生产"的信息差。这是本项目对"非标定制品电商"这一品类的核心贡献。

### 亮点四：订单状态机（架构收敛）

全系统唯一流转规则表 + 终态封口 + 脏数据拦截 + 全链路日志，配合**参数化单元测试**覆盖全流转表。

### 亮点五：安全与测试不是装饰

- 上传三重校验（路径穿越 / 伪装图片 / 透明通道）
- UGC 私有目录隔离 + 审核可见性
- JWT 弱密钥拒绝启动
- 8 个测试类打在真正的风险点上（状态机全流转、运费边界含等于、并发陈旧状态、上传安全、JWT 校验）

### 亮点六：工程规范完整

统一响应封装 + 全局异常 + 逻辑删除 + 事务 + 幂等种子脚本 + 设计规范文档 + 完整毕业设计文档（用例图/时序图/ER 图/物理表设计）。
