# 用户设计好美甲之后的操作流程（方案）

> 状态：方案稿 v1（2026-09-12）
> 范围：从「设计台点下保存」开始，到订单完成/复购为止的完整用户旅程。

## 一、我的核心看法

**1. 「完成即转化」是这个流程的第一原则。**
穿戴甲是按副定制的低价非标品（￥39/副），用户在设计台点保存的那一刻购买意图最成熟——
保存动作和购买动作之间每多跳一个页面，转化就掉一截。所以设计台的出口必须直接给出
购买动作，而不是把用户扔回"我的设计"列表再让他找按钮。

**2. 设计必须"快照化"后才能进入交易，这是定制商品的命根子。**
素材库是活的（商家随时改色卡、下架贴花），订单里的甲必须按下单那一刻的样子生产。
因此：保存设计 = 序列化五指完整配置（params JSON）+ 渲染预览图（html2canvas 截图上传），
购物车和订单项只引用这个不可变快照。项目里 `OrderItem.designParams/previewUrl`
已经按这个思路建好了，方向是对的。

**3. 流程主干已经存在，真正缺的是"设计台出口"和"订单详情的所见即所得"。**
后端 designs/cart/orders/pay + 自提码 + 商家发货都已就绪，前端我的设计/购物车/结算/订单
四页也已实现。不必重构流程，补齐三件事即可（见第四节）。

## 二、目标流程全景

```
设计台(创作)                      交易链路                        售后/复购
──────────────          ──────────────────────────────          ──────────────
点「保存设计」   ──►  设计快照落库(params+预览图)
     │
     ├─ 弹层三选一 ○ 继续编辑(留在设计台)
     │             ○ 保存并加入购物车 ──► 购物车页(可多副/改数量/删除)
     │             ○ 保存并立即结算 ──► 结算页(自提选店 / 配送选地址 + 留言)
     │                                        │
     └─ 「我的设计」列表 ◄────────────────────┘
        (重新编辑/加入购物车/下单/删除)          创建订单(模拟支付)
                                                │
                                    订单状态机：待付款→待制作→制作中
                                                →已发货/待自提→已完成
                                                │
                                    订单详情 = 预览图 + 参数清单(所见即所得)
                                                │
                                    完成后：评价晒图 / 一键复购(再买一副)
```

## 三、现有能力盘点（不重复造轮子）

| 环节 | 已有 | 备注 |
|---|---|---|
| 设计快照 | `POST/PUT /api/designs`（name/params/previewUrl/price） | params = 五指全量配置 JSON |
| 预览图 | 设计台 `capturePreview()`（html2canvas）→ `/designs/upload/preview` | 保存时自动截图 |
| 购物车 | `POST /api/cart`（designId+quantity）、列表/改数量/删除 | Cart 项 = designId 引用 |
| 结算 | `POST /api/orders`（deliveryType/storeId/addressId/remark） | 自提免运费+自提码，配送带快递单号 |
| 支付 | `POST /api/orders/{id}/pay`（模拟） | |
| 订单快照 | `OrderItem.designParams/designName/previewUrl/price/quantity` | 订单不受素材库后续变更影响 |
| 状态机 | 待付款→待制作→制作中→已发货/待自提→已完成，`OrderStatusLog` | 商家端 MerchantOrder 发货操作 |
| 售后 | Review 评价体系 | |

## 四、需要补的三件事（按优先级）

### 1. 设计台出口改造（核心，半天）
`save()` 现在保存成功后 `router.push('/my-designs')` 直接把用户带离创作现场。
改为保存成功后弹出"完成"浮层，三个去向：
- **继续编辑**（留在设计台，浮层关闭）
- **加入购物车**（`POST /cart {designId}` → 成功提示 → 可去购物车）
- **立即结算**（`POST /cart` → 跳 `/checkout`）

未登录点保存：跳登录页并带 redirect（路由守卫已支持），登录回来继续。
名称未填：就地行内提示（已有 ElMessage，可升级为输入框标红）。

### 2. 订单详情"所见即所得"（核心，半天）
订单详情展示 OrderItem 的 previewUrl 大图 + 参数清单（甲型/长度/每指甲色与图案，
从 designParams JSON 解析），并加一行安心话术："按此预览与配置手工制作"。
这是定制品信任的关键：用户确认"我买的就是我设计的"。

### 3. 闭环小件（各 1-2 小时）
- 「我的设计」卡片加"再次编辑"（带 editingId 回设计台，已有能力）与"一键复购"（再买一副）
- 订单完成后引导评价（Review 已有）
- 购物车空态给"去设计一副"入口，回流设计台

## 五、暂不做（防止范围膨胀）

- 真实支付对接（模拟支付已满足演示）
- 甲片尺寸分码（当前均码 + 订单 remark 可备注）
- 分享海报/小程序码（列为 P2）
- 设计的"素材漂移"兜底：素材被商家修改后，旧设计按当前素材渲染会有细微差异——
  毕业设计范围内接受，文档记录即可。

## 六、验收标准

- [ ] 设计台保存后出现三选一浮层，三条路径都能走通
- [ ] 未登录保存 → 登录后回到设计台继续保存
- [ ] 购物车可对同一设计改数量、删除，结算金额 = 39 × 数量
- [ ] 自提订单有自提码，配送订单可填快递单号
- [ ] 订单详情能看到下单时刻的预览图与参数清单
- [ ] 完成订单可评价、可一键复购
