## 三、已修复（P0）：文件路径解析错误

### 现象

1. 商家端「素材管理」页顶部弹出红色提示 **"网络异常，请稍后重试"**；
2. 待审核 UGC 贴纸的预览列不显示图片，退化成「代码渲染」标签；
3. 控制台报 `GET /api/materials/142/image → 404`。

### 根因

`FileService` 用 hutool 的 `FileUtil.file("uploads/")` 解析运行时目录，
而 **hutool 会把相对路径按 classpath 根解析**，于是：

```
期望：E:\jly\backend\uploads\20260919\8e1af31b....png      ← 文件真的在这里
实际：E:\jly\backend\target\classes\uploads\20260919\...   ← 解析到了这里，不存在
```

而 `WebConfig` 的静态资源映射用的是 `Paths.get(uploadDir).toAbsolutePath().normalize()`（按 user.dir 解析，正确）。
**同一份文件，走静态映射 200，走接口 404** —— 两条路径解析基准不一致。

诊断日志（临时插入后已移除）实锤：

```
storedPath=[/uploads/20260919/8e1af31b....png]  uploadDir=[uploads/]
resolved=[E:\jly\backend\target\classes\uploads\...]  exists=false  isFile=false
userDir=E:\jly\backend
```

### 影响面

- UGC 待审/驳回素材的图片读取（素材管理页、设计台「我的上传」）
- **所有上传功能的落盘位置**：素材图、模板封面、设计预览快照、头像、UGC 贴纸、评价晒图
  （同一处 `FileUtil.file` 也被上传逻辑使用，属同一 bug 的另一半）

### 修复

`FileService.java` 中 4 处 `FileUtil.file(...)` 改为 JDK 原生构造，与 `WebConfig` 语义对齐：

| 位置 | 修改前 | 修改后 |
| --- | --- | --- |
| 上传目录 | `FileUtil.file(storageDir, subDir)` | `new File(storageDir, subDir).getAbsoluteFile()` |
| 上传目标 | `FileUtil.file(dir, fileName)` | `new File(dir, fileName)` |
| 读取根目录 | `FileUtil.file(rootDir).getAbsoluteFile()` | `new File(rootDir).getAbsoluteFile()` |
| 读取目标 | `FileUtil.file(root, relativePath).getAbsoluteFile()` | `new File(root, relativePath).getAbsoluteFile()` |

### 修复后实测

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 已审核素材 `141/image`（匿名） | 404 | **200**（1146 B） |
| 待审素材 `142/image`（商家/上传者） | 404 | **200**（1302 B） |
| 待审素材 `142/image`（匿名） | 404 | **404**（正确，未审内容不可见） |
| 商家上传图片 | 落盘位置错 | 正确落到 `backend/uploads/20261013/` ✓ |
| UGC 贴纸上传 | 目录未创建 | 正确落到 `backend/private-uploads/20261013/` ✓ |
| UGC 审核通过后匿名可读 | — | **200** ✓ |
