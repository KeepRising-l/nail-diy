# NailDIY 数据库与部署指南

> 本文说明如何在**另一台电脑**上把项目快速跑起来，以及数据库脚本的使用方式。
> 文中命令均在本机实测通过（Windows 11 + Git Bash）。

---

## 一、环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | **17**（必须） | Spring Boot 3.3 要求 Java 17 |
| Maven | 3.8+ | 构建后端 |
| Node.js | 18+ | 构建前端（推荐 20/22） |
| MySQL | 8.0+ | 数据库 |
| Python | 3.8+ | 仅生成演示数据时需要（可选） |

**检查环境**

```bash
java -version        # 应输出 17.x
mvn -v               # 应输出 Maven 3.8+
node -v              # 应输出 v18+
mysql --version      # 应输出 8.x
```

## 二、数据库脚本说明

项目提供两个 SQL 脚本，位于 `backend/src/main/resources/`：

| 脚本 | 用途 | 什么时候用 |
| --- | --- | --- |
| **`schema.sql`** | **全量建库**：创建 `nail_diy` 库 + 15 张表 + 素材种子 + 模板种子 | **全新环境用这个**（可重复执行） |
| `migration.sql` | 素材模块重构迁移：给已有旧库补字段、迁移旧数据 | **仅已有旧数据的库**用一次，全新环境不要用 |

### 2.1 schema.sql 包含什么

```
CREATE DATABASE IF NOT EXISTS nail_diy ...     ← 建库（utf8mb4）
USE nail_diy;

15 张表：
  user / store / material / template / design / cart / address
  orders / order_item / order_status_log / review / favorite / notice
  after_sale（售后申请） / notification（消息通知）

种子数据：
  material   115 条（甲型 8 / 色卡 30 / 贴图 30 / 参数化款式 10 / 装饰 17 / 效果层 20）
  template   6 条（含封面图引用）
```

> 脚本使用 `DROP TABLE IF EXISTS` + 重建，**可重复执行**，但会清空已有数据 —— 生产环境慎用。

### 2.2 执行建库

```bash
cd backend/src/main/resources

# 方式一：命令行
mysql -uroot -p < schema.sql

# 方式二：指定字符集（中文不乱码，推荐）
mysql -uroot -p --default-character-set=utf8mb4 < schema.sql

# 方式三：已有库时
mysql -uroot -p nail_diy < schema.sql
```

**验证建库结果**

```bash
mysql -uroot -p --default-character-set=utf8mb4 -e "
  use nail_diy;
  show tables;
  select type, count(*) from material group by type;
"
```

### 2.3 已有库升级（补售后与通知两张表）

如果你用的是**更早建好的库**（缺少 `after_sale` 与 `notification`），执行下面两句即可补齐，
**不影响已有数据**：

```sql
USE nail_diy;

CREATE TABLE IF NOT EXISTS `after_sale` (
    `id`            BIGINT        NOT NULL AUTO_INCREMENT,
    `order_id`      BIGINT        NOT NULL,
    `user_id`       BIGINT        NOT NULL,
    `type`          VARCHAR(20)   NOT NULL DEFAULT 'REFUND_ONLY',
    `reason`        VARCHAR(50)   NOT NULL,
    `description`   VARCHAR(500)  NOT NULL DEFAULT '',
    `images`        JSON          DEFAULT NULL,
    `amount`        DECIMAL(10,2) NOT NULL,
    `status`        VARCHAR(20)   NOT NULL DEFAULT 'PENDING',
    `reject_reason` VARCHAR(200)  NOT NULL DEFAULT '',
    `handle_time`   DATETIME      DEFAULT NULL,
    `create_time`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time`   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`       TINYINT       NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_order` (`order_id`),
    KEY `idx_user_status` (`user_id`, `status`),
    KEY `idx_status` (`status`)
) ENGINE = InnoDB COMMENT ='售后申请表';

CREATE TABLE IF NOT EXISTS `notification` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT,
    `user_id`     BIGINT       NOT NULL,
    `type`        VARCHAR(30)  NOT NULL,
    `title`       VARCHAR(100) NOT NULL,
    `content`     VARCHAR(500) NOT NULL DEFAULT '',
    `biz_id`      BIGINT       DEFAULT NULL,
    `biz_type`    VARCHAR(30)  NOT NULL DEFAULT '',
    `is_read`     TINYINT      NOT NULL DEFAULT 0,
    `read_time`   DATETIME     DEFAULT NULL,
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `deleted`     TINYINT      NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    KEY `idx_user_read` (`user_id`, `is_read`),
    KEY `idx_user_create` (`user_id`, `create_time`)
) ENGINE = InnoDB COMMENT ='消息通知表';
```

> 带完整字段注释的版本见 `backend/src/main/resources/schema.sql` 末尾。

## 三、快速启动（三步）

### 步骤 1：配置环境变量（必填）

后端启动**强制要求**两个环境变量，代码里没有默认值：

| 变量 | 说明 |
| --- | --- |
| `MYSQL_PASSWORD` | MySQL 的 root 密码 |
| `JWT_SECRET` | JWT 签名密钥，**必须 ≥ 32 位**，否则拒绝启动 |

```bash
# Git Bash / Linux / macOS
export MYSQL_PASSWORD=你的MySQL密码
export JWT_SECRET=你的随机长密钥至少三十二位以上abcdefghijklmn

# Windows CMD
set MYSQL_PASSWORD=你的MySQL密码
set JWT_SECRET=你的随机长密钥至少三十二位以上abcdefghijklmn

# Windows PowerShell
$env:MYSQL_PASSWORD="你的MySQL密码"
$env:JWT_SECRET="你的随机长密钥至少三十二位以上abcdefghijklmn"
```

> `JWT_SECRET` 可以随便填一串长字符串，只要长度 ≥ 32 位即可。**不要把它提交到仓库。**

### 步骤 2：启动后端（8080）

```bash
cd backend
mvn spring-boot:run
```

**如果 `mvn` 命令不可用**（脚本损坏或未加入 PATH），可以显式指定 Maven 与 JDK：

```bash
export JAVA_HOME="D:/develop/JDK17"
"D:/develop/maven3.9.9/apache-maven-3.9.9-bin/apache-maven-3.9.9/bin/mvn.cmd" spring-boot:run
```

> 本机实测：Maven 位于 `D:/develop/maven3.9.9/apache-maven-3.9.9-bin/apache-maven-3.9.9/`，JDK 17 位于 `D:/develop/JDK17`。

**启动成功的标志**

```
Tomcat started on port 8080 (http)
Started NailDiyApplication in 2.7 seconds
```

**健康检查**

```bash
curl http://localhost:8080/api/health
# 期望：{"code":200,"message":"成功","data":{"status":"UP"}}
```

### 步骤 3：启动前端（5173）

```bash
cd frontend
npm install        # 首次运行需要，已有 node_modules 可跳过
npm run dev
```

**如果 `npm` 不可用**，可直接用 node 执行 vite：

```bash
node node_modules/vite/bin/vite.js --port 5173
```

打开 `http://localhost:5173` 即可。

> Vite 已配置代理：`/api` 与 `/uploads` 自动转发到 `http://localhost:8080`，前端无需额外配置跨域。

## 六、目录结构说明

```
jly/
├── backend/                      Spring Boot 后端
│   ├── src/main/java/com/diy/nail/
│   │   ├── controller/           26 个接口控制器
│   │   ├── service/              18 个业务服务（含 OrderStateMachine / AfterSaleService）
│   │   ├── mapper/               MyBatis-Plus 数据访问
│   │   ├── entity/ dto/ vo/      实体 / 请求 / 响应对象
│   │   ├── security/             JWT 过滤器 + Security 配置
│   │   └── config/               Web / MyBatis-Plus / Jackson 配置
│   ├── src/main/resources/
│   │   ├── schema.sql            ★ 全量建库脚本
│   │   ├── migration.sql         旧库迁移脚本（新环境不用）
│   │   └── application.yml       配置（密码与密钥从环境变量注入）
│   ├── uploads/                  公开上传目录（素材图 / 封面 / 设计快照）
│   └── private-uploads/          私有上传目录（待审 UGC，不对外映射）
├── frontend/                     Vue 3 前端
│   ├── src/engine/               ★ 四个渲染引擎（contours / patternStyles / polishOverlays / decoGems）
│   ├── src/components/           NailArt（甲片渲染）/ HandModel（手模）/ MaterialThumb
│   ├── src/views/                22 个页面（merchant/ 商家端，admin/ 管理端）
│   ├── src/router/               路由 + 三级角色守卫
│   └── scripts/                  演示数据生成脚本（Python）
├── design-system/                视觉设计规范
└── docs/                         项目文档
```

**两个上传目录的区别（重要）**

| 目录 | 存放内容 | 访问方式 |
| --- | --- | --- |
| `uploads/` | 公开素材、模板封面、设计快照、头像、晒图 | 通过 `/uploads/xxx` 静态访问 |
| `private-uploads/` | **待审核**的 UGC 贴纸 | **不映射静态资源**，只能通过 `GET /api/materials/{id}/image` 鉴权访问 |

## 七、常见问题

### Q1：启动报错「JWT 密钥必须不少于 32 位」
`JWT_SECRET` 没设置或太短。设一个 ≥32 位的字符串即可。

### Q2：启动报错「Access denied for user 'root'@'localhost'」
`MYSQL_PASSWORD` 不对，或者 MySQL 没启动。先用 `mysql -uroot -p` 手动连一次确认。

### Q3：启动报错「Unknown database 'nail_diy'」
还没建库，先执行 `schema.sql`（见第二节）。

### Q4：前端页面能打开，但接口全部报错
后端没启动，或者不在 8080。检查 `curl http://localhost:8080/api/health`。

### Q5：`mvn` 命令找不到 / 报脚本损坏
不必修复 `mvn`，直接用完整路径调用（见第三节步骤 2）。本机实测 Maven 可用，路径为
`D:/develop/maven3.9.9/apache-maven-3.9.9-bin/apache-maven-3.9.9/bin/mvn.cmd`。

### Q6：上传图片后，图片显示 404
检查 `uploads/` 目录是否存在于 **backend 目录下**（不是 `target/classes` 下）。
本项目已修复过一个相关缺陷：早期代码用 hutool 的 `FileUtil.file("uploads/")` 解析相对路径，
而该 API 会按 **classpath 根**解析（解析到 `target/classes/uploads`），与静态资源映射（按 `user.dir` 解析）
指向不同目录，导致"同一文件静态能访问、走接口却 404"。现已统一改为 `new File(...)`。

### Q7：控制台报 `favicon.ico 404`
已提供 `frontend/public/favicon.svg` 并在 `index.html` 中引用，正常不会再报。若仍有，清一下浏览器缓存。

### Q8：中文显示乱码
- MySQL 命令行加 `--default-character-set=utf8mb4`
- 后端已在 `application.yml` 强制响应字符集为 UTF-8

### Q9：`mvn` 清理 `dist` 目录时被拦截
本机沙箱有批量删除保护，前端构建时可用 `npm run build -- --emptyOutDir=false` 绕过。

## 八、生产部署建议

当前配置面向开发环境，上线前需要调整：

| 项 | 开发环境 | 生产建议 |
| --- | --- | --- |
| CORS | `allowedOriginPatterns("*")` | 收敛为具体域名 |
| 支付 | 模拟实现 | 接入真实支付沙箱 |
| 前端资源 | Vite dev server | `npm run build` 产物 + Nginx 托管 |
| 接口代理 | Vite proxy | Nginx 反向代理 `/api` 与 `/uploads` 到后端 |
| 数据库 | root 账号 | 独立业务账号 + 最小权限 |
| 密钥 | 环境变量 | 密钥管理服务（KMS / 配置中心） |
| 上传目录 | 本地磁盘 | 对象存储（OSS / COS） |
| 日志 | 控制台 | 落盘 + 集中采集 |

**Nginx 参考配置**

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/naildiy/dist;
    index index.html;

    # 前端 SPA 路由
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 上传文件
    location /uploads/ {
        proxy_pass http://127.0.0.1:8080;
    }
}
```
